3. The Rho Glitch
The Problem: Mismatch Between Analytical and Numerical Rho

Rho measures how much an option's price changes when interest rates change by 1%. For BlackScholesProcess, both analytical ({{ results.option_1_rho_analytic|floatformat:6 }}) and numerical ({{ results.option_1_rho_numeric|floatformat:6 }}) calculations {% if results.bs_rho_difference < 0.001 %} match perfectly (difference: {{ results.bs_rho_difference|floatformat:6 }}). {% else %} show a small difference of {{ results.bs_rho_difference|floatformat:6 }}. {% endif %}

The Glitch: For BlackProcess, the analytical rho ({{ results.option_2_rho_analytic|floatformat:6 }}) and numerical rho ({{ results.option_2_rho_numeric|floatformat:6 }}) show a significant mismatch of {{ results.black_rho_difference|floatformat:6 }}. This happens because the analytical calculation doesn't account for the constraint that dividend yield equals risk-free rate (q = r).

Result: The analytical rho is wrong, but the numerical calculation (which bumps rates and reprices) correctly captures the true sensitivity of {{ results.option_2_rho_numeric|floatformat:6 }}.

4. Correction
The Solution: Manual Correction for BlackProcess

The Fix: For BlackProcess, the correct rho sensitivity is the sum of the standard rho and the dividend rho: Corrected Rho = rho + dividendRho

Calculation: Standard rho ({{ results.option_2_rho_analytic|floatformat:6 }}) + dividendRho ({{ results.dividend_rho|floatformat:6 }}) = Corrected rho ({{ results.option_2_rho_corrected|floatformat:6 }})
